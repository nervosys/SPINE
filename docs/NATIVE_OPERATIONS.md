# Native development-candidate operations

The current candidate supports Windows x64 headless core, CLI, and HTTP gateway. Linux and macOS source portability is not a substitute for archive acceptance on those platforms. Custom mesh cryptography awaits independent review; use the candidate in a trusted local environment. Native origin clients share a single-user trust boundary. A task worker separately authorizes explicitly configured coordinator keys.

## Build and install

Install Rust 1.89 or newer and `protoc`; current validation uses Rust 1.98.1. Run `python scripts/package_candidate.py` from the repository. It builds the three binaries in release mode and writes a local archive and SHA-256 checksum under `artifacts/`. No account or publication operation occurs. The manifest identifies the base commit, dirty state, source digest, toolchain, and dependencies. A development candidate is not a tagged release.

Verify the archive checksum against its adjacent `.sha256` file, extract it into a clean location, and add its `bin` directory to PATH. Verify each member against `SHA256SUMS`. Preserve the dependency inventory and license when redistributing; transitive license obligations require review before public distribution. Run `spine --help` to confirm installation. `python scripts/smoke_candidate.py ARCHIVE` independently verifies and extracts the archive, then exercises its binaries with fresh temporary state.

Create separate writable node directories. Copy `examples/single-node.toml` to the first directory as `spine.toml`, and `examples/mesh-worker.toml` to the second. Start `spine-core` in each directory. Origin TCP is on the configured port, WebSocket on port + 1, QUIC on port + 2 (only in a build with `--features quic`), and, only in a build with the `research` feature, the cluster listener on port + `cluster.port_offset`. The namespace has its own port. The gateway HTTP listener uses `metrics_port + 1`. Allocate every port separately when changing configurations.

`SPINE_CONFIG_PATH` selects an explicit file and fails if it is missing or invalid. Otherwise startup reads the local `spine.toml`, or uses defaults when absent; environment overrides follow. Explicit malformed configuration never falls back silently. `spine deploy --config FILE` validates the file and passes its full configuration through a temporary snapshot to a sibling `spine-core` binary, without overwriting the working directory's configuration. Relative persistence paths resolve in the child's working directory.

Run the gateway with `SPINE_CONFIG_PATH` selecting `examples/gateway.toml`, and a bearer token from your secret manager. Configure the model and IronGate environment variables as described in the [agent-web quickstart](AGENT_WEB_QUICKSTART.md). The gateway binds the configured host. Keep plain HTTP/TCP on loopback or behind an authenticated TLS boundary; the gateway bearer token does not create native session tenancy.

## Build with research features

`spine-core` has a `research` cargo feature, off by default. The default daemon (`cargo build -p spine-core`) has no cluster node or event listener and no human HTML-to-HLB transpile on `Navigate`. The WASM execution layer is not part of this feature. The `[cluster]` configuration section is still parsed and is ignored without the feature. The latent encoder, neural protocol, agentic runtime, session transfer and autonomous loop that used to sit behind it are not in the daemon in any build; they are recorded in `research/spine-protocol-research/README.md`.

To get a research daemon, build with `cargo build -p spine-core --features research`. `spine-cli` forwards the feature (`--features spine-cli/research`) so one build can produce both binaries, because `spine deploy` runs the sibling `spine-core` binary; `scripts/deploy.sh` (local cluster) builds with it.

Without the feature, `Navigate` still fetches and stores the page but stores an empty HLB binary, as it does when transpilation fails. `StoreKnowledge` stays local to the session. The `spine-core` binary has no command that answers `unsupported_without_research`; the retired swarm and speech-act commands no longer exist in the command set, so a client cannot construct them.

## Connection and TLS policy

`server.max_connections` defaults to 256 and bounds active native TCP, WebSocket, and optional QUIC connections together, including unfinished handshakes. `max_connections_per_ip` defaults to 50. Excess connections are refused immediately. Admission is released on disconnect or task cancellation, and empty IP entries are removed. Native TLS and WebSocket upgrades have ten-second deadlines. After that the client must send a spine-wire v1 `HELLO` within `server.hello_timeout_secs` (default 10); the daemon answers `HELLO_ACK` or closes with `CLOSE(timeout)` and releases the admission, so a socket that connects and stays silent holds one slot for at most that long. Version 1 is the only version; the daemon negotiates a 16 MiB maximum frame and `max_inflight` of 1, so a connection processes one request at a time. `idle_timeout_secs` is a frame-receive deadline, including time waiting for the next header, restarted by every frame including `PING`; it defaults to 300 seconds, and an idle connection receives `CLOSE(timeout)`. The SDK bounds TCP connection and TLS handshake setup at ten seconds each. Core and SDK choose the Ring TLS provider explicitly, independent of dependency feature unification. Native writes have a 30-second deadline and close the stream after an incomplete write. Dispose of a native SDK client after cancelling an in-flight request.

The namespace has separate inbound and outbound TCP budgets. `[namespace] connection_limit` defaults to 64 for each direction. `handshake_timeout_secs` and `write_timeout_secs` default to 10, `frame_timeout_secs` to 60, and `queue_timeout_secs` to 5. Every duration must be between one and 3,600 seconds and the connection budget between one and 1,024. The frame deadline includes idle time and receipt of the entire frame; quiet sockets close and later work redials. A caller cancellation during a mesh write retires that socket. Application RPC is never transparently replayed; query the original task UUID after an uncertain outcome. Mesh contact/address registries each hold at most 1,024 entries, the shared inbound queue holds 64 envelopes, and frames hold at most 4 MiB. These are component bounds, not a process-wide memory guarantee or sustained-load result. Mesh WebSocket/QUIC admission remains experimental.

The native wire is spine-wire v1 (`docs/spec/00-wire.md`). A frame is capped at the negotiated `max_frame` (16 MiB; 64 KiB before `HELLO`) before any body is allocated. A compressed body declares its uncompressed length, which must fit the same bound and is checked before decompression; the zstd window is capped at 2^23 bytes (8 MiB). Compression is off unless the sender enables it and applies only to bodies of 1 KiB or more. TCP, WebSocket and QUIC use the same frame codec, and an unsupported version is closed with `unsupported_version`. Large resources continue to use chunked transfer. The wire does no encryption of its own: confidentiality and authentication on the native path come from TLS only.

`tls.enabled` applies to native TCP and WSS on `port + ws_port_offset`. Install a trusted server certificate and use `wss://` for WebSocket clients. `mutual_tls = true` requires an explicit, readable CA file and client certificate; a missing CA fails startup. Server-only TLS does not infer mTLS from a CA file found nearby. A configured client CRL requires mTLS and accepts PEM or DER; missing or invalid files fail startup. The optional native QUIC feature refuses startup with configured TLS until it can enforce the same certificate policy. Development certificates now start near generation time and leaf certificates last one year; replace existing expired test certificates explicitly. Certificate rotation still requires restart.

See `examples/mutual-tls.toml` and `examples/irongate.toml` in the archive. These controls cover native origins. The research-feature cluster listener and the diagnostics have their own trusted-network boundary; mTLS does not grant per-user roles or protect every auxiliary port.

## Configure outbound navigation

Native `Navigate` and WASM navigation use the same `[outbound]` policy. The default permits HTTP/HTTPS to public unicast addresses, denies private, loopback, link-local, multicast, documentation and reserved ranges, and rejects URLs containing credentials or fragments. All DNS answers must pass; the request connector uses those checked addresses. Ambient proxy settings are disabled. This policy does not govern operator-configured model endpoints or signed mesh resource endpoints.

Requests never follow redirects, even within the same origin. Compressed responses are refused and the client requests identity encoding. HTML must be valid UTF-8. Failures return stable `outbound_*` errors without URL or upstream body contents. A failed navigation preserves the loaded page.

Defaults are `enabled = true`, `max_response_bytes = 2097152`, `timeout_secs = 30`, and `max_concurrent = 16`. Further defaults are `allowed_ports = [80, 443]`, `read_timeout_secs = 10`, `max_concurrent_per_caller = 4` and `allow_link_local_exceptions = false`. A URL whose effective port is not in `allowed_ports` (at most 16 entries, none 0) is refused with `outbound_invalid_port` before any DNS lookup, unless its origin is an `internal_origins` exception, which names its own port; this stops a client using `navigate` to scan ports. `read_timeout_secs` (1 to 300, capped at `timeout_secs`) bounds the wait for each body chunk, so a stalled or slow-drip server cannot hold an admission permit for the whole deadline; it answers `outbound_timeout`. `max_concurrent_per_caller` (1 to 256, capped at `max_concurrent`) limits how many fetches one session runs at once, so one client cannot take every permit; a session over the cap receives `outbound_busy` while other sessions proceed. The deadline covers DNS, connection and response consumption; dropping the fetch future releases admission. Native commands remain serial, so closing a native connection does not necessarily interrupt a command already running; its deadline still applies. Excess concurrent requests fail immediately with `outbound_busy`. Response bytes are counted incrementally, including responses without a content length. The maximum configurable response is 8 MiB, timeout 300 seconds and concurrency 256; URLs are limited to 8 KiB and DNS answers to 64 addresses. These bound fetched bytes, not the parser/transpiler's total memory use.

Use `enabled = false` to disable both navigation paths. To serve an intentionally internal resource, set `internal_origins = ["http://127.0.0.1:8088"]`. Exceptions match the exact normalized scheme, host and effective port and permit every path at that origin. They do not permit redirects or relax response/time limits. Treat an exception as authority granted to every native client; keep the list narrow. Configuration is refused if an exception names a literal link-local (169.254.0.0/16, fe80::/10) or unspecified (0.0.0.0, ::) host, such as the cloud metadata address, unless `allow_link_local_exceptions = true`. Loopback and private-range exceptions need no flag. The daemon logs one warning per configured exception at start. The archive's `examples/internal-navigation.toml` demonstrates this opt-in. The conservative address policy can deny unusual public ranges; use reviewed explicit origins when required. Network-level egress policy remains useful for routes and services specific to a deployment.

## Use MCP tools

Start the core, then configure your MCP host to launch `spine mcp --addr 127.0.0.1:8080`. The adapter discovers the core's schemas and exposes `spine_content_hash` and `spine_html_parse`; these map to the native `spine.content/hash` and `spine.html/parse` tools. It forwards actual calls to the core and preserves structured results. Unknown tools produce a JSON-RPC error. No browser navigation, publication, task assignment, process, or model execution is exposed through this adapter.

For an mTLS origin use `spine mcp --addr HOST:PORT --tls --domain SERVER_NAME --ca CA_FILE --client-cert CLIENT_CERT --client-key CLIENT_KEY`. Keep private key files access controlled. Plain TCP remains suitable for trusted local clients. The bridge uses newline-delimited UTF-8 JSON-RPC, reserves stdout for protocol responses, and sends diagnostics to stderr, following the [MCP stdio specification](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports). It targets MCP revision 2025-06-18.

The adapter processes one call at a time, limits each stdio line to 8 MiB, and bounds a forwarded call at 30 seconds. A transport failure discards the native connection; restart the MCP process before further tool calls. Notifications do not produce responses. This read-only subset has no asynchronous cancellation executor or Streamable HTTP endpoint. Clean candidate acceptance exercises initialization, schemas, tools, errors, ping, and mTLS from a separate process; runtime acceptance inside individual third-party hosts remains separate.

## Monitor and stop

Core `/health` and `/ready` are on `metrics_port`. `/health` reports process liveness: it stays HTTP 200 during admission pressure and returns 503 while draining. `/ready` describes capacity for new native connections and sessions. It returns 503 if draining, at the global connection limit, or at the session limit, with fixed `reasons` (`draining`, `connection_capacity`, `session_capacity`), `accepting_connections`, `accepting_sessions`, current counts and configured limits. Existing clients can continue to work while readiness is false. A readiness sample does not reserve capacity or establish availability for a particular client IP.

Session capacity counts the retained session map, including restored records. `[server].session_retention_secs` defaults to 3600 and accepts 1–2592000 seconds. A session is protected while its connection handler runs, including awaited commands. Handler completion or cancellation starts its detached retention timer. A peer closing during an awaited command may be noticed after that command completes or reaches its deadline. The watchdog (default 600 seconds) expires detached sessions and removes their session knowledge, rate state and cluster registration. Idle socket cleanup starts this timer rather than immediately deleting session state. Admission and cluster imports share a serialized capacity check; duplicate or unsafe import IDs are refused. Native session ownership and reconnect/resume APIs remain open work.

Core persists sessions and session knowledge together in `spine-sessions-v1.json` in the state directory. Saves use a same-directory temporary file, file sync and atomic replacement, with a 64 MiB serialized snapshot limit. Native session and legacy session-knowledge changes are periodically snapshotted; a command response is not a snapshot durability acknowledgement. Abrupt termination can lose changes since the last save. Windows power-loss durability depends on the filesystem; this is not an encrypted backup. Corrupt, unsupported or over-capacity snapshots stop startup rather than exposing partially restored state. Startup drops expired records and their knowledge, preserving the separate legacy `cluster_shared` knowledge scope; durable mesh tasks and task knowledge use their existing SQLite storage and are unaffected.

On the first start without a manifest, core migrates legacy `sessions/*.json` and `knowledge/*.json` files with 16 MiB per-file and 64 MiB combined limits. Records without timestamps receive one retention interval, and future timestamps are clamped to startup time. Once the manifest exists it is authoritative: old files are ignored, so expiry cannot be undone by a restart. Keep the manifest in backups. Retain legacy directories only as protected migration backups; do not remove the manifest to trigger an unintended re-import. Lowering `max_sessions` below the saved record count requires an explicit state migration before startup. Native retention does not bound every process cache or the number of knowledge entries within a live session.

Readiness also reports namespace state (`disabled`, `local_only`, or `peers_known`), task enablement, pending application RPC count and an aggregate outbound snapshot. Known peers do not prove current remote availability. Missing optional seeds, a disabled namespace or disabled outbound navigation do not alone make the local origin unready. These endpoints do not probe required model providers, certify storage durability or cover every bridge dependency. Diagnostics and the dashboard remain inside the trusted operator-network boundary.

`/metrics` includes namespace lookup, announcement rejection, replica send/failure, expiry counters and pending RPC gauge. Native metrics are `spine_native_connections_active`, `spine_native_connections_limit`, `spine_native_connections_per_ip_limit`, and `spine_native_connections_rejected_global_total` / `spine_native_connections_rejected_per_ip_total`. A rejected connection increments exactly one rejection counter; the global limit takes precedence when both limits are full. These counters include admission before TLS/WebSocket/QUIC handshakes. The session gauge is populated from the actual session map when scraped, including restored sessions.

Outbound metrics include `spine_outbound_enabled`, `spine_outbound_requests_active`, `spine_outbound_requests_limit`, `spine_outbound_calls_started_total`, `spine_outbound_calls_succeeded_total`, `spine_outbound_calls_failed_total`, `spine_outbound_calls_cancelled_total`, `spine_outbound_calls_denied_total`, `spine_outbound_calls_busy_total`, `spine_outbound_calls_timed_out_total`, `spine_outbound_response_limit_failures_total`, and `spine_outbound_bytes_received_total`. Failures include denied/busy/timed-out/response-limit subsets; cancellation is separate and counts a polled fetch future dropped before completion. Active requests count admission permits held during DNS and transfer. Received bytes count body chunks delivered to the fetcher, including a chunk rejected for exceeding the bound; headers and early content-length refusals are excluded. These are component counters, not network-wire throughput or model-generation measurements.

Snapshots are advisory and independent counters can change while read. Counters reset on process restart. Metric names and categories are fixed; no origin, URL, input, client IP or session ID labels are exported. The dashboard contains session identifiers and counts, not navigation URLs or command payloads.

Inspect the namespace with `spine name --addr 127.0.0.1:8080 status`. It reports the local agent ID and public key, learned contacts, and connectivity. Do not put private keys in logs or tickets. Worker task capabilities are queried through a pinned peer identity, as documented in the quickstart.

Stop an interactive core with Ctrl+C. It refuses new sessions, persists sessions, and waits for active connections up to `shutdown_timeout_secs`. Close clients first for a clean drain. A CLI-managed core also drains when its parent signals its private stdin pipe or exits; this is a process lifecycle channel, not a network administration API. An abrupt kill cannot drain, but namespace, resource, task, and durable task-knowledge writes already acknowledged locally remain in SQLite. The acceptance harness covers both forced worker restart and managed shutdown.

## Metrics and readiness reference

The listener binds `[server].host` on `metrics_port` (defaults `127.0.0.1` and 9090, so loopback only). Binding, authentication and exposure are unchanged: it has none, so keep it on loopback or a trusted network. `/metrics` is the Prometheus text format 0.0.4: the process registry (`spine_sessions_active`, `spine_commands_total`, `spine_command_latency_seconds`) followed by the families below, each with `# HELP` and `# TYPE`. Counters end in `_total`. Labels come from fixed sets (`result`, `reason`, `outcome`), never a name, key, peer, session, URL or address.

Gauges: `spine_sessions_limit`; `spine_draining` (1 while draining); `spine_native_connections_active`, `_limit`, `_per_ip_limit`; `spine_outbound_enabled`, `spine_outbound_requests_active`, `spine_outbound_requests_limit`; `spine_execute_permits_in_use` and `spine_execute_permits_limit` (`execute_binary` programs running against their limit); `spine_persistence_failing` (1 while the last session snapshot failed); `spine_resource_store_available` (0 when its accounting cannot be read), `spine_resource_store_bytes`, `spine_resource_store_blobs` (blobs held, from the store's in-memory accounting; 0 while it is unreadable) and `spine_resource_store_limit_bytes` (the store's real limit, not a constant); `spine_namespace_records_held` (records in the local store); `spine_namespace_enabled`.

Counters outside the namespace: `spine_native_connections_rejected_global_total` and `_per_ip_total`; `spine_outbound_calls_{started,succeeded,failed,cancelled,denied,busy,timed_out}_total`, `spine_outbound_response_limit_failures_total`, `spine_outbound_bytes_received_total`; `spine_namespace_cache_lookups_total{result="hit|stale_hit|negative_hit|miss"}` and `spine_namespace_cache_evictions_total`; `spine_namespace_owner_renewals_total{outcome="renewed|failed|publish_failed|skipped_rotated"}` (owner renewal, counted from process start: `renewed` is a record re-signed and persisted, `failed` a pass that could not plan or a record that could not be persisted, `publish_failed` a renewed record the mesh publication of which failed (it is also `renewed`), `skipped_rotated` a rotated name the node key is no longer allowed to sign, once per name per pass; a rising `skipped_rotated` means an owner must renew with the name's current key).

With the namespace enabled, also: gauges `spine_namespace_peers` (addressable keyspace peers), `spine_namespace_pending_lookups`, `spine_mesh_pending_calls`; counters `spine_namespace_{lookups_started,lookups_resolved,lookups_timed_out,requests_answered,announcements_accepted,announcements_rejected,announcements_declined,unroutable_peers,greetings_answered,greetings_rejected,replicas_sent,replicas_failed,records_expired,envelopes_unauthenticated,agent_id_mismatches,equivocations,log_store_failures,log_rows_dropped}_total`, `spine_namespace_records_refused_total{reason="need_log|succession"}`, `spine_namespace_succession_logs_total{outcome="adopted|oversize|rejected"}` and `spine_namespace_log_fetches_total{outcome="sent|suppressed|adopted"}` and `spine_namespace_seeds_total{outcome="reached|failed"}` (the seeds dialed once, at join). A rising `records_refused_total` or `equivocations_total` means peers are announcing records this node will not accept; `log_store_failures_total` above zero means the durable succession log book could not be written (or a bad row could not be deleted) and offers were refused for it, and `log_rows_dropped_total` counts rows dropped when the book was loaded at start; `replicas_failed_total` rising means replication is not reaching its targets. Not exported because the daemon keeps no such counter: negative-cache entry count, per-reason outbound failure codes.

`/ready` keeps its fields and adds `warnings`. It returns 503 only when `reasons` is not empty. Reasons: `draining`, `session_capacity`, `connection_capacity`, `persistence_failing` (the last session snapshot write failed; clears on the next success), `storage_unavailable` (the resource store's accounting could not be read). Warnings never fail `/ready`: `namespace_no_peers` (namespace enabled, no seeds configured, no peers: the first or a solitary node) and `namespace_seeds_unreachable` (seeds or DNS seeds were dialed at join and none answered, whether or not peers have since arrived; when no seed was dialed, for example DNS seeds that resolved to nothing, it is inferred from seeds being configured and no peer known). A peerless node is deliberately still ready, because a mesh's first node has no peers by design; alert on the warning or on `spine_namespace_peers == 0` where peers are expected. Model and bridge dependencies are not probed.

## Back up and recover

Stop the node and copy its entire state directory to an access-controlled backup, including mesh identity, externally owned publication keys and signed records, `spine-names.sqlite`, and `spine-sessions-v1.json` (plus any protected legacy migration backups). For live SQLite backups use the SQLite online backup API; never copy only the main database while its WAL is active. Apply owner-only Windows ACLs or restrictive Unix permissions to every key and backup. This checkout does not automate encrypted backup storage or key escrow.

Restore into an empty directory and start with the preserved configuration and identity. Reconnect to seeds; learned contacts, caches, and remote replicas are rebuilt rather than trusted from disk. Confirm identity with `name status`, fetch a known resource, and check a completed task through its coordinator. Changing the mesh or publication key changes the DID authority; it does not transfer ownership of old names. Rotate by publishing under the new key and updating pinned peers through an authenticated operator channel.

Back up before any upgrade. Upgrade all nodes and clients together: appended native enum variants and application mesh payloads are development wire changes, and mixed old/new versions are not supported. Existing name/resource storage namespaces remain; tasks use separate `spine-tasks-v1` and `spine-task-knowledge-v1` namespaces. Older binaries cannot operate those task records. Restore the pre-upgrade backup for rollback when incompatible storage behavior is introduced; do not infer compatibility from the unchanged source version 2.0.2.

## Supported task policy

Only HTML parsing and content hashing execute remotely. Tasks are persisted before acknowledgement, owner scoped, bounded, and idempotent for an identical owner/UUID/specification. Conflicting reuse fails. The encrypted TCP handshake pins the recipient key and binds the signed caller to the authenticated connection; unsupported application transport modes are refused. Dependency results can supply a JSON pointer as the next task's text input. Cancellation prevents pending work and wins over completion; a running read-only function may finish computing locally, but cannot publish a completed result after cancellation. Deadlines include queue time. On restart interrupted read-only work returns to pending within its original deadline. No shell, filesystem, network, or model execution is delegated. The earlier speech-act command no longer exists on the wire.

Knowledge keys are immutable within an owner. Repeating the same key/value is idempotent; changed content requires a new versioned key. Removing an allowed coordinator prevents further access or scheduling by that key, without deleting its stored records. Capacity: a worker holds at most 256 tasks and 256 knowledge entries, and each owner at most 64 pending or running tasks and 64 knowledge entries; limits are reported by `capabilities`. When the task store is full, a new task evicts the terminal (completed, failed or cancelled) task with the oldest creation time, across all owners, never a pending or running task nor a task that a pending or running task depends on; if none qualifies the submission is refused, and an evicted task answers exactly like an unknown one. Knowledge is never evicted, so reaching the owner quota or the worker capacity returns a distinct error, and there is no delete operation yet (it needs a new `TaskOperation` variant in `spine-protocol`). A task deadline is wall-clock time from submission, so it includes dependency waiting and any worker downtime: an interrupted task whose deadline passed during an outage fails on restart instead of re-running. Re-running on restart is only safe for tools without side effects. A tool result over 256 KiB fails the task with an error naming the limit and the actual size. Keep completion IDs and provenance in your coordinator state. RPC timeout is an uncertain outcome: query status with the original UUID after reconnecting, rather than creating another task.

Public seed operations, independent cryptographic review, broader task execution, Linux/macOS archives, load targets, and multi-user native session isolation remain separate completion gates in the [status report](COMPLETION_STATUS.md).
