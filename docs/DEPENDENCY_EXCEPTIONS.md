# Dependency maintenance exception register

Owner for every entry: **SPINE release maintainer** (repository maintenance role). Reviewed: **2026-11-19**. Next review: **2026-12-19**, or before any public release, whichever occurs first. Changes to the lockfile or new vulnerability advisories trigger an earlier review. This register records temporary maintenance exceptions for the local development candidate; it does not approve a public release.

`deny.toml` ignores twelve informational unmaintained advisory identifiers. It suppresses no vulnerability advisory. RUSTSEC-2026-0459 (`libsqlite3-sys`) was cleared on 2026-11-20 by moving to `rusqlite` 0.43, which required raising the MSRV from 1.88 to 1.89; the lockfile change is expected to leave zero vulnerability advisories, to be confirmed by the CI `audit` and `deny` jobs. The audit also reports fourteen unmaintained package/version warnings (`unsafe-libyaml` is among them but outside the dependency-policy graph, so it needs no ignore entry; `tokio` and `rustix` additionally carry unsound-only warnings that are not ignored); `rustls-pemfile` is no longer in the root lockfile (2.2.0 remains in the `research/` lockfile, via `kube-client`). The counts in this paragraph were not redone after the 2026-11-24 pruning below. Unmaintained dependencies can acquire undisclosed or newly discovered flaws, so passing the current advisory database is limited evidence.

**Pruning, 2026-11-24.** `cargo deny` 0.19.0 was run offline against the local advisory database for the root manifest (with and without `--all-features`) and for `research/Cargo.toml`, using this same `deny.toml` (there is no `research/deny.toml`; CI gives the research run no other configuration). RUSTSEC-2025-0119 (`number_prefix`) was removed: the crate is in neither lockfile. Eight further entries are reported "not encountered" by the root run (RUSTSEC-2024-0384, 2024-0388, 2024-0436, 2025-0012, 2026-0192, 2026-0370, 2026-0371, 2026-0372) and RUSTSEC-2025-0134 joins them after the `rustls-native-certs` 0.8 move; all nine are still present in `research/Cargo.lock`, which is checked against the same file, so they stay and are marked research-only below. RUSTSEC-2025-0057 and RUSTSEC-2025-0141 were reported unmatched by CI for the root manifest but matched locally (`fxhash` 0.2.1 and `bincode` 1.3.3 are in the root lockfile), so they are kept; the local advisory database may differ from CI's. Separately, the research `cargo deny` run reports RUSTSEC-2024-0449 (`unsafe-libyaml` 0.2.11 via `serde_yaml` -> `kube-client` -> `spine-k8s`) as an error: it is not ignored and was not changed here.

**Workspace split, 2026-11-21.** `spine-browser`, `spine-agentic` and the other experimental crates now live in the separate `research/` workspace, which has its own `research/Cargo.lock`. Entries below whose example path runs through them (the GUI, accessibility and font stack, and the direct `spine-agentic` use of `chrono`) concern that workspace, not the root lockfile, and `chrono` still reaches the root workspace through other crates. The review date and advisory counts above were not redone for the split; re-run the audit against both lockfiles at the next review.

At each review, run `cargo audit --json` and `cargo deny check advisories licenses` against the locked dependencies, examine newly reported advisories, and inspect affected dependency paths. Remove obsolete exceptions only after checking the lockfile as well as the resolved graph. Any vulnerability advisory must be remediated or block the affected candidate; this register grants no vulnerability exception.

The license allowlist, Ring license clarification, and `epaint` font exception remain repository policy. Cargo-deny passing checks that policy; public distribution still requires the release maintainer to preserve applicable license notices and review the actual distributed artifacts. Reproduce the local candidate gates with `python scripts/release_gate.py` and consult [completion evidence](COMPLETION_STATUS.md).
