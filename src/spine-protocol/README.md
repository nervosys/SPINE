# spine-protocol

Low-latency communication protocols for SPINE

Part of [SPINE](https://github.com/nervosys/SPINE), an agentic-first web
stack. This crate is published from the SPINE workspace and versioned with
it; see the [workspace README](https://github.com/nervosys/SPINE#readme) for
how the pieces fit together and the
[CHANGELOG](https://github.com/nervosys/SPINE/blob/master/CHANGELOG.md) for
what changed in this release.

## Conformance vectors

`docs/spec/00-wire.vectors.json` holds test vectors for spine-wire v1: valid and invalid bodies and frames and handshake cases, with the exact bytes in hex. They are generated by `scripts/wire_v1.py`, a second, independent implementation in Python (standard library only) written from `docs/spec/00-wire.md`. Check them with `python scripts/wire_v1.py check docs/spec/00-wire.vectors.json`; `tests/conformance_vectors.rs` runs the same file against this crate. A new implementation in any language can use the file the same way: the format is described at the top of it.

## Features

- `quic` (default): the QUIC transport (`QuicEndpointBuilder`, `QuicTransport`).
There is no `research` feature. The crate has no dependency on any crate under
`research/`. The native wire is spine-wire v1: `connection::Connection` speaks
length-prefixed frames with a version, type, flags and request id after a
`HELLO`/`HELLO_ACK` handshake, and `native` maps the `Message` set onto those
frames (bodies are deterministic CBOR: a request is a command from a closed set of 19, a response is `{ok: ...}` or `{err: {code, message}}`; see `body` for the error codes and `wirefmt` for the byte-string helpers). There is no sealing: confidentiality
comes from TLS or the session layer. The Chameleon latent-space key, `SpineConnection`, `connect_auto`,
the protocol evolution framework, `TitansLatentCodec` and the pre-shared-key AES
layer are not part of this crate: the first four are in the experimental,
unreviewed `research/spine-protocol-research` crate and the AES layer was
removed. `LatentVector` and the neural-codec types (`EncodedFrame`,
`NeuralCodec`, `CodecRegistry`, `EmbeddingRequest`, ...) moved to the same research
crate with the `Message` variants that carried them.

## Workspace dependencies

None. The `research/` crates `spine-nostd` and `spine-embedded` were dev
dependencies of the integration tests; those tests moved to
`research/spine-protocol-research`.
